## Fixes found by review

This release is a correctness pass over `0.7.0-alpha.11`, not a feature release.

### The two new settlements could never spawn

`mountain_spirit_shrine` and `spirit_beast_keeper_camp` had worldgen entries but no
`neoforge:biome_modifier`, so they were only reachable through `/place feature`. Both now
have biome modifiers and appear naturally in mountain and forest biomes.

### The shrine altar was another dead array core

The shrine placed a lone `spirit_array_core` on its top step, which can never form without
four spirit soil arms and four corner focus blocks. It now builds the complete array, the
same fix applied to settlement workshops.

### Residents spawned in the wrong places

The anchor derived standing spots from the layout enum alone, but each builder places its
buildings at different offsets, so on `HALL` and `RING` layouts residents could end up
inside walls or on bare ground. The feature now records the real offsets at generation time,
stores them on the anchor, and persists them through save/reload as `SpawnOffsets`.

### Spirit beasts often failed to spawn

Beasts were created at one hard-coded corner offset, which could be water, a wall or paving.
They are now placed by a ring search outward from the anchor onto open ground.

## Verified in a live server

Placed one spirit spring village and read the anchor NBT:

```
{Palette: "dark_oak", Initialized: 1b, Layout: 3, WarmupTicks: 40,
 SettlementType: "spirit_spring_village", SpawnOffsets: [I; -4, 1, 0, 4, 1, 0, 0, 1, -4]}
```

Then queried the entities at that site:

- settlers: `Test passed. Count: 3`, nearest named `Spirit Spring Keeper`
- spirit beast: `Test passed. Count: 1`

Six spirit spring villages placed at different coordinates produced 2 palettes and all 4
layouts, confirming the per-site randomness.
